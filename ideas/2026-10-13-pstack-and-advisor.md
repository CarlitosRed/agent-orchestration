## Take, in priority order
1. **A verification skill and feature map for OUR app** (create/maintain-verification-skill). A project-local skill that launches the free demo, drives each screen like a user, captures screenshots and a transcript as evidence, cleans up without deleting the evidence, and keeps a feature map (one file per feature: how to reach it, how to drive it, what proves it). Fits us twice: desk-environment.md says NO automated lane runs the browser goal tests, and the demo RECORDING Carlos wants needs exactly this driver. Maintain loop: source wave per feature, one live pass, at most one PR of proven corrections.
2. **/correct: a rule-to-enforcer table.** Our process-leaks log (L1 to L41) is the "mistake classes" list. Repeats cost us rounds: approval comment format (L37, L40), alias claims without a probe (L41), squash-landing deletions (L39). Fix at the highest level that works: gate or CI check first, template second, prose rule last, and keep one table pairing each CONTEXT-RULES rule with what enforces it. First candidates: gate rejects an approval whose first words are not the verdict; ledger rows need one probe per alias class.
3. **Review lead-judgment buckets (interrogate).** Reviewer output sorted into Act on / Consider / Noted / Dismissed with the model that raised it; a finding raised independently by two models is the strongest signal. Idea for rule 19: on Tier 3, run Claude and Codex round 1 in parallel instead of in series, and merge the lists, to cut rounds (history 7 to 9 on the worst PRs).
4. **Decision log with evidence pointers (show-me-your-work).** Our decisions.md is prose. Add a short evidence column (sha, comment id, file:line) and a "start" row per chat; at the end of a milestone audit the log against the transcript and have the other vendor scan it. Also feeds the private portfolio case study.
5. **Patch-id rule for approvals (autopilot-full).** An approval stays valid after a rebase or "merge main" when the PR's own patch is unchanged. We re-reviewed #20 three times after merging main. This needs a gate change (Tier 3 PR), so it is a later item.
6. **Advisor (official, experimental).** Pair a cheaper main model with Opus as advisor, called before locking a plan, on the same error twice, and before declaring done. Setting: `advisorModel` (or `/advisor opus`, or `--advisor`). Sonnet 5.5 main accepts Opus 5 or later. Facts from the docs: Anthropic API only (not Bedrock, Vertex or Foundry); stays off if `DISABLE_TELEMETRY` or another flag-fetching switch is set; each call re-reads the full transcript uncached and counts toward plan limits; toggling it keeps the prompt cache; subagents inherit it; `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` removes it. For us the cost point matters: this PM chat is long, so keep calls to a few (plan decisions, round-3 stops, before merges). Also from the thread: a read-only scout subagent named exactly `Explore` on haiku replaces the built-in one; our clerk is already haiku.
