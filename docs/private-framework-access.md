# Private framework repo access
Moved here from `adapters/README.md`, which keeps a pointer under the same heading because the workflow templates name it in their error text.

Existing projects adopt the token-free clone by updating the fetch step in both copied `.github/workflows/` files through a project-owned PR. Merging a framework release, making its repository public, or changing `framework.pin` does not update those copies. The v0.7.0 templates require the token before attempting a clone; projects retaining those steps still need their secret until the workflow update is installed.

Both CI workflows shallow-clone the framework repo named in `framework.pin`. With the updated fetch steps from both templates installed in the project, a public framework pin can be cloned without `FRAMEWORK_PIN_TOKEN`: each step attempts a plain clone first and uses the token fallback if that attempt fails. A pin pointing at a **private** fork or mirror needs the authenticated fallback: a GitHub Actions runner's default token only reaches the repo the workflow itself runs in, not a different private repo, so a plain `git clone` of a private pin fails cold with a cryptic `fatal: could not read Username for 'https://github.com'`, not a permissions-denied message that points at the real cause. (Originally found live on `advance-po-reader#52`, its own leak log L58, while the framework repo was still private.)

If your pin points at a private repo, add a project secret named exactly `FRAMEWORK_PIN_TOKEN`: a fine-grained GitHub personal access token scoped to read-only (`contents: read`) on the framework repo only, created by the Program Owner (never by an agent - this is a credential) and added under that project's own repo Settings -> Secrets and variables -> Actions. Both templates fall back to it automatically when the plain clone fails, and fail with a named, actionable error (pointing back at the `adapters/README.md` heading "Private framework repo access") when both the plain clone and the token are unavailable - the gate itself would refuse a PR on a required check that can't even run, which is the correct failure direction (never silently skipped).
